# Progressive Fire Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** 경보·대피는 즉시, 불·연기와 경로 차단은 공간 연결을 따라 단계적으로 진행하는 로컬 시연.
**Architecture:** Controller가 시험 발화 위치를 검증하고 공간 그래프의 도달 시간을 계산한다. 같은 StateSnapshot의 fire_simulation과 blocked/routes를 화면이 소비하며 Runner는 이 시험 원인을 기존 직선 연기에 중복 합성하지 않는다.
**Tech Stack:** 기존 Python/Pydantic, React/Three.js/TypeScript. 새 의존성 없음.
**Spec:** docs/superpowers/specs/2026-11-11-progressive-fire.md

## Global Constraints
- 최초 로컬 구현 후 #195에서 통합 검증·PR·머지를 승인받음. 기존 AI·감지기 경보, 23명 인원과 서버 경로 소비 구조 보존.
- 2m 구역 격자, 열린 경로 연결만 확산. 실제 물리 예측으로 표시하지 않는다.
- 경로와 시각 자료는 같은 서버 상태에 포함한다.

## Review Focus
- 닫힌 문·같은 평면 좌표 다른 층에 즉시 전파되지 않는다.
- 구역 내부 한 지점에서 발생해도 먼 문을 즉시 모두 막지 않는다.
- 중복 입력·반복 경보는 성장 시간을 초기화하지 않는다.
- 해제·초기화·다중 화재·개인 방의 상태가 서로 섞이지 않는다.
- 연결 만료 때 화면이 혼자 확산하거나 최신 경로처럼 안내하지 않는다.

## 검증 기록
- 서버 전체 959개, 프론트 전체 262개 시험 통과. TypeScript, lint, 계약 생성물 검사 통과.
- 저장소 검사(362개 파일)와 로컬 커밋 후 프로덕션 빌드 통과. 기존 3D 청크 500kB 초과 경고가 남았다. 검증 뒤에는 이 기록만 갱신했다.
- 위치가 문/통로 위일 때 즉시 해당 경로 차단, 닫힌 문 전파 제한, 구역 안 실제 벽 관통 방지, 잘못된 발화 위치 거부를 회귀 시험으로 확인했다.
- 독립 검토에서 발견한 닫힌 문 경로의 위험 표본 누락과 구역 내부 벽 연결을 수정했다. WFI 계단 B 대표점도 벽 밖 지점으로 보정했다.
- 실제 브라우저(8046/5186), 음소거 유지: 3층 304호 발화 9초에 22명 이동·1명 탈출·통로 4개 차단 → 48초에 16명 탈출·3명 멈춤·통로 88개 차단, 평상시 대비 유도등 방향 5개 변경.
- 해제 시 차단이 모두 풀리고 남은 사람도 탈출해 23명 완료. 초기화 후 경보 0·차단 0·대기 23명 확인.
- 1인칭 별도 실행: 화재 직후 23명 이동, 휴대폰의 약 3m 후 우회전 → 계단 2층에서 1층 안내를 확인했다. 선택한 사람은 확산보다 빨리 나가서 그 사람의 목적지 변경은 화면에서 직접 보지 못했다.
- 도면으로 304호 한쪽을 클릭한 실행: 그 좌표에서 작은 불꽃이 시작하고 4초에 23명이 이동하며 먼 문은 차단되지 않는 것을 확인했다.
- 음성 청취·실제 센서/AI 연동·장시간 5개 방 부하 시험은 이번 범위에서 실행하지 않았다.
- 로컬 전용. 푸시·PR·머지·배포 없음.
