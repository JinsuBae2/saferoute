## 입력 크기 개선 시도 — 미채택

이번에는 같은 xiazh 가중치·confidence0.25·500ms·window1500/min2를 유지하고 개발 입력 크기만
512로 줄인 후보를 7개 전체에 한 번 실행했다. 그 결과를 본 뒤 작은 입력에서 감지가 늦어지는
한계를 확인해, 별도 계획으로 768 후보를 7개에 한 번 실행했다. 두 번째 크기 비교까지만 수행했다.
평가 자료는 사용하지 않았으며 선정된 640 설정과 기준·정답·매칭은 변경하지 않았다.

| 크기 | FIRE TP/FP/FN | SMOKE TP/FP/FN | 정상 FIRE/SMOKE FP | SMOKE 최대 대응 지연 | 분석/예상·폐기 | 판단 |
|---|---|---|---|---|---|---|
| 640, 기존 #105 | 1/1/0 | 2/1/0 | 0/0 | 2000ms | 358/358·0 | 선정 유지, 정밀도 미달 유지 |
| 512, 이번 | 1/1/0 | 2/0/0 | 0/0 | 5000ms | 358/358·0 | 불꽃 정밀도·연기 지연 미달, 미채택 |
| 768, 이번 | 1/1/0 | 2/1/0 | 0/1 | 4500ms | 356/358·2 | 정상 오탐·정밀도·지연·누락 미달, 미채택 |

512의 연기 정밀도 100%는 빠른 검출을 회복한 결과가 아니라 한 사건의 첫 대응이 5초로 늦어진
결과와 함께 해석해야 한다. 768의 정상 SMOKE FP1을 137.320초에 환산하면 26.22건/시간이며
실제 1시간 측정값은 아니다. 전송·EOF·로그 무결성은 두 후보 모두 통과했지만 성능 합격과 다르다.
모두 Windows CPU·자체 loopback 실측이다. 서버·30분 지속 실행을 새로 수행한 것은 아니며
재생 대기를 포함한 read→completion 값으로 순수 추론 속도 개선을 주장하지 않는다.

[512 원본 재계산](../../deploy/resource-checks/2026-11-10-ai-input512.json),
[768 원본 재계산](../../deploy/resource-checks/2026-11-10-ai-input768.json)에 각 영상의 원본·정답·예측
해시, 모든 사건 지표, 전송·처리 건수와 runtime을 남겼다. 원본 로그는 실행 PC의
`runs/a01-9-candidate512/`, `runs/a01-9-candidate768/`에 보존했다.
512의 최초 실행은 잘못 적은 asset_id로 사전 거부(분석0·제어기 시작 전)됐고 올바른 기존 ID로
수정했다. 768 후처리에서 폐기0을 가정한 확인문이 실패해 실제 폐기 수를 원본과 대조하도록
고쳤다. 두 실패 기록을 보존했고 성능이 나쁘다는 이유로 추론을 반복하지 않았다.

재현은 [기존 전송 검증 명령](a01-readiness-validation.md)에 개발 7개 manifest와 asset_id 전부,
imgsz만 바꾼 별도 설정·새 출력 폴더를 지정한다. 각 실행의 예측과 development 정답을
[전체 평가 도구](a04-suite-evaluation.md)로 대조한다. 기본 설정·평가 기준은 유지한다.

## 기준 승인 후 실행 순서

1. [승인 기록을 반영한 설정 문서](evaluation-freeze-proposal.json)의 기준·목록을 사용한다.
   기준 승인/실행 미동결 상태이며 지금까지의 시험 합격 선언이 아니다.
2. 담당5의 실제 정답 검수·주석 완료 후 코드·모델·설정·실행 영상·정답 해시와 동결자·UTC시각을
   기록한다. 변환 영상은 전체 프레임·시각 동등성과 정답 연결을 먼저 확인한다.
3. 지원 서버 CPU 4스레드·단일 AI 작업자·자체 loopback에서 고정 5개 목록을 처음 한 번 실행한다.
   실패·미시도·누락도 보존한다. 재실행은 사유·별도 실행 ID를 남기고 최초 결과를 대체하지 않는다.
4. [전체 집계](a04-suite-evaluation.md)로 TP/FP/FN 정수를 먼저 합산한다. 정상 오탐/길이를 합산하고
   지연은 전체 대응 사건의 최댓값을 사용한다. 영상별 비율의 평균은 사용하지 않는다.
5. 필수 자료·실행·지표 없음 또는 N/A이면 INCOMPLETE, 모두 평가 가능하나 기준 미달이면 FAIL,
   전부 충족할 때만 해당 프로토콜의 PASS다. INCOMPLETE여도 확인된 미달을 숨기지 않는다.
6. 담당5가 대응·집계 결과를 독립 대조하고 실제 완료된 범위만 이슈에 기록한다.
