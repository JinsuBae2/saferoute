# A04 전체 영상 집계 — 입력 누락·부분 집계 구분

2026-11-10, #118. [단일 영상 평가](a04-event-evaluation.md)의 `evaluate()`를 그대로 사용해 원본 예측 로그와 정답을 다시 검증하고 전체 지표를 합산한다. 모델 재실행·조건 조정·독립 평가 완료·성능 합격 판정 기능은 아니다.

## 입력과 실행

`python -m tools.evaluate_ai_suite --manifest runs/suite.json --output runs/suite-result.json`

입력 목록은 명시적으로 모든 대상 영상을 열거한다. 경로는 **목록 파일이 있는 폴더 기준**이며 절대 경로도 가능하다. 아래는 형식 예시이며 실제 완료 로그/정답 경로로 바꾼다.

```json
{
  "schema_version": 1,
  "entries": [
    {
      "asset_id": "dev-candle-match",
      "predictions": "a01-105-xiazh/ai/RUN_ID/ai-predictions.jsonl",
      "ground_truth": "../data/expected/ai/development/dev-candle-match.json"
    },
    {
      "asset_id": "dev-joss-smoke",
      "predictions": "a01-105-xiazh/ai/OTHER_RUN_ID/ai-predictions.jsonl",
      "ground_truth": "../data/expected/ai/development/dev-joss-smoke.json"
    }
  ]
}
```

한 목록 안의 split·설정 전체(모델 경로/해시 포함)·매칭·runtime 선언은 같아야 한다. 서로 다른 모델·설정·환경은 목록을 나눠 비교한다. runtime 선언이 같다는 것이 실제 장비 동일성의 독립 인증은 아니다. 구형 로그의 runtime이 모두 null이면 그대로 보존하고, null과 기록된 runtime을 혼합하지 않는다.

평가용 실행은 #9/#12의 최종 모델·조건 합의/동결과 담당5의 검수 완료 후에만 진행한다. 이 도구는 팀 서명이나 최종 목록을 자동 검증하지 않는다. **호출자가 준 목록이 전체 분모**이므로 동결된 대상 목록과 누락 없이 일치하는지 먼저 대조해야 한다. 빈 목록·중복 asset_id·잘못된 목록 구조는 영상별 입력 파일을 읽기 전에 거부한다.

## 실패 처리와 결과 의미

- 각 항목은 기존 평가기의 원본 해시 연결·실제 VIDEO_AI 출처·전송/EOF·완료·정답 구간·독립 검수 조건을 통과해야 한다. 저장된 평가 요약 JSON만 받아 신뢰하지 않는다.
- 목록 asset_id와 정답 식별자 불일치, 같은 영상 SHA-256의 중복, split/설정/매칭/runtime 선언 혼합도 거부한다.
- 유효한 목록의 특정 입력이 없거나 미완료/검수 미충족이면 해당 `cases`에 `FAILED`, 오류, 읽을 수 있었던 입력의 해시를 남기고 나머지 항목도 확인한다. 모음 일관성 검사에서 실패한 경우 이미 계산된 영상별 보고서도 보존한다.
- 하나라도 실패하면 `status=INCOMPLETE`, `aggregate=null`, `common=null`, 종료 코드 1이다. 일부 영상의 성공 지표를 전체 결과로 합산하지 않는다.
- 전체 입력이 통과하면 `status=COMPLETE`, 종료 코드 0이다. `validated_videos`는 모음 조건까지 통과한 수이며 **모델 성능 합격 수가 아니다.** `performance_verdict`는 항상 `NOT_ASSESSED`다.
- 새 출력 파일만 만들고 기존 파일을 덮어쓰지 않는다. 목록 자체가 잘못되면 결과 파일을 만들기 전에 거부한다. 입력 목록/출력 오류는 종료 코드 1과 오류 메시지로 알린다.

결과에는 목록 원본 바이트 SHA-256, 요청 asset 목록, 영상별 원본 입력 해시·전체 기존 평가 결과, 정상/위험 구분·사건/실패 목록, 공통 설정/실행 환경 선언을 보존한다. 처리 도중 파일 읽기와 검증에 실패한 이유도 결과에서 제외하지 않는다.

## 전체 지표

| 항목 | 집계 방식 |
|---|---|
| TP / FP / FN | 클래스별 영상 결과의 정수 합계. 영상 사이의 사건은 병합하지 않음 |
| 정밀도 / 재현율 | 합산한 TP/(TP+FP), TP/(TP+FN). 영상 비율 평균을 쓰지 않고 분모0은 null |
| 지연 | 영상 시각 기준 대응 사건 지연의 전체 목록·수·평균·최댓값. FN은 별도 보존 |
| 정상 오탐 | 전체가 정상인 영상의 FP와 길이를 각각 합산한 시간당 비율. 정상 영상이 없으면 분모0·비율null |
| 장면군 | scene_id별 asset 목록과 그룹 수. 같은 촬영 장면의 여러 파일을 독립 장면 수로 과장하지 않음 |
| 처리량 | 분석 샘플 합계 / 영상 루프 소요시간 합계. 어느 영상이라도 시간이 없으면 합계 시간·처리량null 및 기록된 영상 수 표시 |
| 늦은 샘플 | 폐기 수 합계. 순수 모델 FPS나 모든 프레임 분석 보장으로 표현하지 않음 |

지연·루프 처리량에는 기존 단일 영상 도구의 한계가 적용된다. 루프 시간은 재생 대기·전송·로그를 포함하고, read→completion은 순수 모델 추론 시간이 아니다. 학습 중복·독립성은 선언을 보존할 뿐 증명하지 않는다. 자동 목표 비교/채택 결정은 수행하지 않는다.

## 검증과 실제 개발 로그 재계산

수계산 fixture 시험은 서로 길이가 다른 정상 영상의 시간당 오탐, 영상별 비율 평균과 다른 전체 정밀도, FN/분모0, 같은 장면군, 영상 경계 사건, 일부 입력 누락 후 나머지 처리, 미완료/검수 미충족·중복·설정/환경/split 혼합 거부, 알 수 없는 처리시간, 상대 경로와 덮어쓰기 방지를 확인한다. fixture의 `evaluation` 표시는 형식 시험용 합성 자료이며 실제 평가 정답을 열지 않는다.

[재계산 증거](../../deploy/resource-checks/2026-11-10-ai-suite-evaluation.json)는 #105의 xiazh0.25 **기존 개발7개 로그**에 새 도구를 실행한 결과다. 7개/5장면군, 총177.690초·정상137.320초, 358샘플·skip0, FIRE TP1/FP1/FN0·SMOKE TP2/FP1/FN0, 정상 오탐0을 기존 결과와 대조했다. 각 원본 예측/GT 해시와 영상별 모든 사건 지표도 동일하다. 새로운 추론·정확도 향상·독립 평가를 주장하지 않는다.

담당5에게는 #30에서 정답5개 검수·polyurethane 주석 완료를, #41에서 실제 설명7개 검수를 요청했다. 팀 모델/사용 조건과 평가 목표는 #9/#12에서 결정 요청 중이다. [평가 동결·인계 순서](evaluation-freeze-and-handoff.md)를 충족하면 고정된 전체 평가 목록을 이 도구로 집계하고 담당5가 일부 대응/집계값을 독립 대조한다.
