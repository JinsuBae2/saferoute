# saferoute 요구사항 명세서

[기획서](01-project-proposal.md) · [개발계획서](02-development-plan.md) · [데이터·인터페이스](05-data-interface-spec.md) · [시험·시연](07-integration-test-demo-scenarios.md)

이 문서는 개발 범위를 기능·입력·출력·예외·검증 기준으로 정의한다. 요구사항은 **검수 기준**이며 구현 현황은 README와 연결 이슈에서 확인한다. F11은 이번에 확정한 구현 예정 항목이다. 완료 여부는 실제 시험 후 기록하며 화면·문서의 존재만으로 완료 처리하지 않는다.

## 1. 목적과 사용 주체

목적은 불꽃·연기·설비 동작의 관측 정보를 받아 위험 구간을 제외한 경로를 계산하고, 설치 지점·표시면별 유도등 명령을 전달하는 것이다. 시뮬레이션은 센서·등기구·연기 변화를 대신해 기술을 검증한다.

| 주체 | 수행하는 일 | 권한·제한 |
| --- | --- | --- |
| 시연 운영자 | 실행 시작·초기화·특정 경보 확인 해제 | 팀 전용 접속. 원인·실행 ID 기록 |
| 관제 사용자 | 관측·경로·단말·연기 정답 확인 | 서버 판단을 표시하며 경로를 직접 계산하지 않음 |
| 별도 유도등 단말 | 자신의 명령 수신·표시·ACK | sign_id별 동작, 오래된 방향 사용 금지 |
| 영상 작업자 | 실제 녹화 영상 추론·관측 전달 | 지정 카메라·구역만 관측 |
| 가상 설비 | 모의 감지·동작·상태 확인 이벤트 | AI 관측으로 표시하지 않음 |
| 시험 담당 | 독립 정답·장애 주입·증거 검수 | 구현 출력을 정답으로 복사하지 않음 |
| 공개 관람자 | 공개 방식 확정 시 시연 조회 | 기본 범위 미정. 조작 API는 별도 인증 필요 |

## 2. 범위와 가정

- 건물은 원주미래산업진흥원 지상 1~3층 공개 안내도를 바탕으로 한다.
- 센서·유도등·출구 사용 조건·치수는 실제 설치 자료가 없어 시연 가정으로 관리한다.
- 실제 영상 추론은 구현한다. 실제 건물 CCTV 접속 또는 영상의 건물 위치 자동 추정은 하지 않는다.
- 시연에서는 별도 브라우저가 유도등 장치를 대신한다.
- 연기 표현은 시나리오 강도이며 실제 농도·확산 해석·독성 판단이 아니다.
- 실제 건물에 없는 우회로를 만들지 않는다. 지하층·옥상·대체 대피공간은 기본 목적지에서 제외한다.
- 실제 인증·비상전원·전기적 고장 대응·현장 피난 안전성 검증은 이번 소프트웨어 구현의 범위 밖이다.
- 지원 서버와 S3를 사용한다. 공개 URL·도메인·심사위원 조작 범위는 미정이다.

## 3. 필수 기능

### F01 실제 불꽃·연기 영상 분석

**입력:** 확보한 영상, 검증된 오픈소스 불꽃·연기 모델·가중치, source_id·구역 매핑, 추론 설정.<br>
**출력:** 출처·시각·영상 위치·클래스·confidence·유효성을 가진 실제 관측 이벤트.

- 불꽃과 연기를 구분하고 미검출 분석·영상 실패를 구분한다.
- source_id를 통해 구역에 매핑한다. 영상 전체 매핑은 실제 발화 좌표 추정이 아니다.
- 지속 감지 조건과 임계값은 평가 전에 고정한다.
- 프레임이 없으면 이전 검출 결과를 새로운 관측처럼 보내지 않는다.
- 미검출·EOF·재연결로 제어기의 기존 경보를 해제하지 않는다.

**예외:** 지원 클래스 없음, 가중치 없음, 영상 열기 실패, 너무 느린 처리, 전송 실패는 명시 오류·관측 불가로 처리한다.  
**수락:** V01의 실제 추론 근거와 입력 연결, V10의 종료·끊김 처리. 수동 샘플은 F01 대체 불가.  
**담당:** 1번.

### F02 설비 신호 시뮬레이션

**입력:** 가상 연기감지기·스프링클러의 독립 이벤트.  
**출력:** 해당 원인의 활성 상태와 경로 재판단 근거.

- 영상 AI가 경보를 내지 않아도 각 설비 이벤트만으로 동작한다.
- 스프링클러는 지정 담당 구역의 동작 신호이며 정확한 발화 좌표가 아니다.
- 경보 이벤트 부재와 장치 상태 확인 실패를 구분한다.
- 시험 공급자는 관제 창과 독립적으로 실행한다.

**수락:** V02에서 각 관측원을 단독으로 작동시켜 다른 관측원의 동시 감지 없이도 반영.  
**담당:** 2번 도구, 5번 시나리오.

### F03 원인별 상태 통합

**입력:** 수락된 관측, 상태 만료, 지정 원인 확인 해제.  
**출력:** 활성 원인 목록, 관측 유효성, 차단 대상, 판단 이유.

- 원인 키는 source_id·hazard_type이다.
- 활성 경보와 VALID·STALE·UNAVAILABLE 관측 상태를 분리한다.
- 다른 관측원의 정상 신호는 기존 경보를 삭제하지 않는다.
- 확인 해제는 지정 원인만 변경하고 담당·시각·이유를 기록한다.
- 새 실행은 INITIALIZING이며 필수 관측과 명시적 시작 확인 전 기본 방향을 내보내지 않는다.

**예외:** 중복·역순·오래된 시각·다른 실행·미등록 ID는 계약에 따라 거부한다.  
**수락:** V03에서 두 원인 중 하나만 해제했을 때 나머지 경보 유지, 관측 만료와 경보 유지 동시 확인.  
**담당:** 2번.

### F04 위험 배제와 경로 계산

**입력:** 검증된 방향 그래프, 사용 가능한 출구, 원인별 차단 상태.  
**출력:** 노드별 다음 지점·출구·경로 또는 안내 불가 사유.

- 위험 노드·통로는 제거한다. 큰 비용만 주어 대안이 없을 때 지나가게 하지 않는다.
- 필수 관측이 유효하지 않은 구간은 운전 중 화재 여부와 관계없이 경로 후보에서 제외한다. 경보가 없는 DEGRADED에서도 남은 그래프로 경로를 계산하며, 출구에 도달할 수 있는 지점은 계속 안내한다.
- 모든 edge 비용은 양수다. 동일 상태에서 같은 결과가 나오도록 동률 규칙을 고정한다.
- 출구의 사용 조건을 확인한다. 닫힌 문과 통행 불가 문을 구분한다.
- 출구 도달 여부·순환 없음·노드 연결 유효성을 검사한다.
- 경로가 있는 사례까지 항상 안내 불가로 반환하면 실패다.

**예외:** 출발점 위험, 모든 출구 차단, 고립된 지점, 관측 부족, 표시할 수 없는 다음 지점을 구분한다.  
**수락:** V04·V05의 독립 정답과 일치. 알려진 위험 통과·순환·잘못된 출구 0건과 정상 경로 제공 모두 충족.  
**담당:** 2번.

### F05 가변 유도등 안내

**입력:** 서버의 다음 지점과 sign_id·face_id별 배치.  
**출력:** DEFAULT·DYNAMIC·NO_ROUTE·UNKNOWN 표시 명령.

- 개인 위치가 아닌 설치 지점을 기준으로 한다.
- 정상 관측 상태의 기본 표시와 화재·관측 장애 시의 동적 안내를 구분한다. 관측 장애만으로 화재 발생을 표시하지 않는다.
- 표시면별 방향은 보는 사람 기준이며 반대 면을 별도 정의한다.
- 안내 불가인 표시면이나 초기화·명령 만료로 판단할 수 없는 단말은 이전 방향을 안전한 경로처럼 계속 표시하지 않는다.
- 하나의 안내 버전에서 서로 모순된 다음 지점이나 순환이 없어야 한다.

**수락:** V06의 정면·반대 면·계단 방향과 명령 내용 일치.  
**담당:** 2번 명령, 3번 표시, 4번 배치.

### F06 기본 건물과 관제

**입력:** 공개 안내도 기반 공간 모델, 서버 스냅샷, 시험용 현재 연기 상태.  
**출력:** 지상 1~3층, 위험 근거·경로·유도등·적용 현황·연기 표현.

- 기본 구조·층 전환·확대·회전·시점 초기화를 제공한다.
- 위험·경로·유도등은 같은 guidance_version으로 표시한다.
- 시험 정답과 실제 제어기 관측은 범례·표시·시각을 구분한다.
- 통신 실패·오래된 정보·일부 단말 미적용을 드러낸다.
- 모델 외관보다 공간 연결과 표시면의 일치를 우선한다.

**수락:** V07의 도면·그래프 대조, V08의 정답·관측 분리.  
**담당:** 3번 화면, 4번 모델.

### F07 반복 실행과 기록

**입력:** 고정 시나리오·설정·새 run_id.  
**출력:** 재현 가능한 상태·명령, 원인부터 적용까지 연결된 로그.

- 시나리오 seed·버전·영상·모델·코드·설정 해시를 기록한다.
- reset은 이전 기록을 삭제하지 않고 새 실행을 만든다.
- 이전 실행 이벤트·명령·ACK가 새 실행을 변경하지 못한다.
- 로그 누락·손상은 증거 부족 또는 오류로 처리한다.

**수락:** V12에서 동일 조건 반복 결과가 일치하고 이전 실행 입력이 거부됨.  
**담당:** 2번 기록·도구, 5번 검수.

### F08 기본 장애 처리

**입력:** 영상·단말·관제·서버 단절, 지연·역순·중복 정보.  
**출력:** 관측 불가·명령 만료·미적용·복구 상태와 원인.

- 영상 종료는 경보 해제가 아니다.
- 화면을 닫아도 제어 프로세스는 유지한다.
- 단말은 만료 명령을 제거하고 재연결 시 신선한 전체 상태를 받는다.
- 서버 재시작 후 새 실행 준비 전 평상시 방향을 자동 재개하지 않는다.
- 일부 단말만 적용되었으면 전체 적용으로 표시하지 않는다.

**수락:** V09·V10·V13 장애 사례. 브라우저 절전 한계는 기록한다.  
**담당:** 1·2·3번, 5번 검수.

### F09 연기 변화 시연

**입력:** 구역별 시간표·표현 강도·가상 관측 규칙·지연·누락.  
**출력:** 공간에 차오르고 다른 구역으로 확대되는 연기 표현, 그에 따른 관측·경로·유도등 변화.

- 연기 정답을 제어기 입력으로 직접 사용하지 않는다.
- 지연·누락이 있으면 관측도 그 영향을 받아야 한다.
- 시나리오는 관제 브라우저가 아닌 별도 실행기에서 진행한다.
- 실제 AI로 시나리오를 시작해도 이후 모의 연기는 실제 AI 예측으로 소개하지 않는다.

**수락:** V08에서 연기 발생 후 관측 전까지의 차이, 관측 후 판단 변경, 누락 사례가 구분됨.  
**담당:** 2번 실행기, 3번 표현, 5번 시간표.

### F10 별도 유도등 단말

**입력:** 자신의 sign_id와 새 명령.  
**출력:** face 표시와 해당 명령의 적용 응답.

- 서로 다른 ID의 단말 2개 이상을 별도 창 또는 기기에서 실행한다.
- 실행·건물·명령 순번·유효기간을 검증한다.
- HTTP 수신만으로 적용 성공 ACK를 보내지 않는다.
- 실제 화면 확인과 서버 ACK를 함께 증거로 남긴다.
- 관제 화면 없이도 명령 수신·표시·ACK가 지속된다.

**수락:** V06·V09·V11. 브라우저 성공을 실제 소방 등기구 인증으로 표현하지 않음.  
**담당:** 3번 단말, 2번 전송·응답.

### F11 Bedrock 상황 설명

**입력:** 제어기의 현재 실행·건물·안내 버전, 활성 경보·차단 대상·선택 경로·안내 불가 사유.<br>
**출력:** 근거 ID가 연결된 한국어 상황 설명과 생성·기준 시각, 준비/성공/실패 상태.

- 오픈소스 감지 결과와 제어기 사실을 설명하며 영상 감지나 경로 계산을 대신하지 않는다. AI 작성 설명임을 표시한다.
- 설명 작업자는 제어기의 읽기 API만 사용한다. 시나리오 정답·미래 상태·원본 영상·비밀정보를 모델 입력에 넣지 않는다.
- 제어와 분리해 호출하며 응답 실행·건물·안내 버전·기한을 검사한다. 늦은 응답은 현재 설명으로 채택하지 않는다.
- 모델·응답 형식·참조 사실 ID를 검사하고 내용은 독립 대조한다. JSON 형식 검증 성공이 사실 정확성을 보장하지 않는다.
- 설명에서 새 통로·경로·행동 지시·안전 선언·경보 해제·단말 적용 완료를 생성하지 않는다. 다음 이동 방향과 적용 상태는 구조화된 제어 결과로 표시한다.
- Bedrock 실패·중단·권한 거부 시 설명을 UNAVAILABLE로 표시하고 경로·명령·ACK는 계속 동작한다. 설명 오류를 전체 제어기 503으로 전파하지 않는다.

**수락:** V15에서 실제 호출 성공, 사실 대조, 오래된 결과 폐기와 설명 장애 중 제어 지속 확인. 모의 응답만으로 완료 처리하지 않는다.<br>
**담당:** 1번 A05 작업자, 2번 계약·배포, 3번 P02 표시, 5번 검수.

## 5. 선택 기능과 제외 범위

선택 기능은 장애물 감지, 추가 복합 화재, 고급 연기 효과, 검토된 대체 대피공간이다. 선택 기능을 추가하더라도 F01~F11의 미완료를 대체하지 않는다. F11은 합의된 개발 범위이며, 설명 장애 시에도 제어가 동작해야 한다는 조건과 설명 기능 자체의 완료 판정을 구분한다.

프론트에서 경로 판단, LLM의 피난 방향 결정, 미래 연기 정답을 이용한 경로 생성, 임의 통로 추가는 구현 방식으로 허용하지 않는다.
