# B06 구역 선택 시험 화재 (#72)

## 위치 지정·점진적 확산 (로컬 구현)

화면의 시험 입력은 `ObservationEvent.ignition_position`에 발화 위치(m)를 보낸다. 도면 클릭은 클릭 지점을, 목록 선택은 구역 내부이면서 벽이 아닌 대표 지점을 사용한다. 이 선택 필드는 MANUAL_TEST/FIRE/ALARM에만 허용되며 서버가 해당 관측 구역·층·벽과 대조한다. 없는 기존 이벤트는 기존 구역 단위 경보 정책을 유지한다.

경보와 대피는 즉시 시작한다. 위치 지정 시험만 2m 격자와 기존 열린 문·복도·계단 연결을 따라 화염·연기가 확산된다. WFI v5는 버전이 일치하는 `data/space/wfi-geometry-v1.json`의 내부 벽을 격자 연결과 발화 검증에 사용한다. 등록된 열린 이동 연결은 문·계단을 통과하는 연결이며, 닫힌 문은 확산 연결에서 제외하되 대피 통로의 위험 검사는 유지한다. 좌표 거리를 쓰고 계단 우회용 경로 비용을 거리로 쓰지 않는다.

`ActiveCause.ignition_position`은 최초 발화 위치를 유지한다. `StateSnapshot.fire_simulation`(선택, 없으면 null)은 `DEMO_GRAPH_V1` 모형, 원인별 발화 위치·경과 시간, 칸별 위치·불·연기를 포함한다. 서버가 같은 상태의 차단·경로·유도등과 함께 발행한다. 1초 단위 확산 갱신 중 차단 집합이 바뀔 때 안내 버전도 증가한다. 화면이 시간을 추측하여 확산시키거나 별도 경로를 계산하지 않는다.

화염 4초/m, 연기 3초/m, 층간 추가 지연 화염 20초/연기 8초, 성장 화염 20초/연기 12초는 **시연용 가정**이다. 실제 연소·기류 예측이나 피난 안전 시간의 근거가 아니다. 화염 도달 또는 연기 값 0.5 이상인 통로를 차단하며, 발화점 0.35m 안의 지점·통로는 즉시 차단한다. 위치 지정 시험을 기존 직선거리 연기에 중복 합성하지 않는다. 실제 AI·감지기 경보와 필수 관측 만료 차단은 그대로 유지한다.

해제는 해당 시험 원인의 확산을 함께 제거하는 시연 조작이며 실제 소화·배연 모형이 아니다. 다른 원인은 남는다. 초기화·방별 실행은 시간과 확산 상태를 공유하지 않는다. 계약 예시는 `data/contracts/valid.json`의 `progressive_manual_fire`와 `progressive_fire_state`에 있다.

## 조작

3D 바로 아래의 **시연** 패널(#139)에서 ① 화재 위치 ② 현재 위치 선택 ③ 시연 시작 순서로 조작한다. 구역을 선택한 것만으로 입력을 보내지 않는다. `시연 시작`은 화재 위치와 내 위치를 모두 골라야 눌리며 등록된 MANUAL_TEST 관측원의 FIRE를, `선택 화재 해제`는 해당 관측원의 FIRE 해제만 보낸다. `시험 화재 모두 해제`는 현재 활성인 등록 시험 FIRE를 순서대로 해제한다. 전체 제어기 reset과 달리 다른 AI·감지기 경보, 관측 장애, 실행 ID와 단말 상태를 초기화하지 않는다.

`초기화`(#130, 처음 이름은 시뮬레이션 재실행)는 시나리오 실행기의 `POST /sim/restart`를 부른다. 실행기가 제어기를 reset하고 새 실행에 다시 붙은 뒤, 자신이 소유한 필수 관측이 유효해지면 arm한다. 모든 경보·시험 화재·단말 상태가 지워지고 연기 시간표가 0초부터 다시 시작하며, 접속한 모든 화면에 적용된다. 밖에서 reset된 실행기는 지금처럼 멈추고, 이 요청을 받았을 때만 다시 붙는다. 개발용 `/sim` 스텁은 이 요청을 지원하지 않는다. 인증이 없으므로 공개 배포에서는 누구나 누를 수 있다. 공개 범위는 #31에서 정한다.

WFI v4는 기존 가상 감지기 관측 구역 12곳에 `MANUAL-{zone_id}`를 추가했다. 모두 `required=false`, `allowed_hazard_types=[FIRE]`, `freshness_ms=3000`이다. 미등록 방·계단 등은 목록에 이유와 함께 비활성으로 보인다. 기존 28개 관측원과 그래프·좌표·통로 비용·표시면은 유지하고 공간·형상·표시 자료·WFI 시나리오 버전만 함께 4로 맞췄다. 설치 장비가 없는 시험 입력이므로 설치 위치는 null이다.

## 상태·오류 처리

- 발생 전 `/api/state`를 새로 읽어 현재 실행·건물 버전을 확인하고 마지막 source_sequence + 1을 사용한다. 관측 시각은 이 응답의 서버 UTC(`generated_at`)를 사용한다. 브라우저 시계 차이로 미래 관측이 되는 것을 피하며, 지연된 요청은 기존 freshness 검사로 거부된다.
- 이벤트에는 zone_id를 보내지 않는다. 등록 source_id가 구역을 정한다. media_time_ms/confidence는 null이며 VIDEO_AI로 가장하지 않는다.
- 한 번에 한 조작만 수행하고 8초 기한을 둔다. 응답 수락과 다음 상태 반영을 구분해 표시한다. 유도등 수락/발행과 단말 APPLIED는 서로 다르다.
- 실패하면 수락을 확인한 건수와 오류를 표시하고 자동 재시도하지 않는다. 통신 단절 시 서버에 반영됐을 수 있으므로 현재 경보 목록을 먼저 확인한다. 모두 해제 도중 실패하면 멈추며 앞서 성공한 해제를 되돌렸다고 표시하지 않는다.
- 외부 reset으로 run_id가 바뀌면 패널 선택·이전 결과를 버리고 진행 중 요청을 중단한다. 이전 실행의 요청은 서버도 RUN_MISMATCH로 거부한다. 새 실행을 자동 arm하거나 정상 관측을 만들어 보내지 않는다.
- 제어 상태 조회가 끊기거나 오래되면 조작을 비활성화한다. 화면을 닫아도 화재는 자동 해제되지 않는다.

## 경로와 다른 작업 연결

경로·표지는 기존 서버의 StateSnapshot을 그대로 사용한다. 구역별 경로 하드코딩과 클라이언트 경로 계산은 없다. 현재 #69의 공통 위치 선택 연결부가 없으므로 이 이슈에서 허용한 구역 목록 선택을 사용한다. `ManualFirePanel`은 별도 구성 요소이며 추후 공통 선택 상태로 연결할 수 있다. #71의 개인 출발점·3D 경로 강조와 #70의 실제 표지 그림은 별도다.

API·접근 주소·프록시·CORS·배포 설정은 변경하지 않았다. 기존 로컬/SSH 내부 접근 범위에서만 사용한다. 새 공개 엔드포인트나 인증 우회는 없다. #28 배포 작업은 포함하지 않는다.

## 검증 기록

- `tests/test_manual_fire.py`: 등록/선택 관측원, 같은 출발점의 두 화재 위치에 따른 경로·명령 일치, 다중 원인 보존, 장애 유지, 중복·미등록·역순·이전 실행 거부.
- `web/src/control/manualFire.test.ts`: 실제 등록 구역, 서버 시각·순번, 미지원 구역, 실행·건물 변경, 원인별/전체 시험 해제, 부분 실패, 빠른 연속 요청, 취소, 자동 재시도 없음, 잘못된 응답.
- 로컬 WFI v4 화면에서 위쪽 통로 발생 → 아래쪽 추가 발생 → 위쪽만 해제 → 시험 모두 해제 → 외부 reset을 확인했다. 같은 `F2-J-E2`에서 위쪽 화재는 EXIT-S / FRONT LEFT, 아래쪽 화재는 EXIT-N / FRONT FORWARD였다. 둘 다 막으면 안내 불가, 전부 해제하면 평상시 79/79 안내로 돌아왔다.
- reset 후 이전 선택·성공 문구가 사라지고 준비 중 상태로 바뀌었다. 해당 시험은 기존 개발 관측 생성기로 필수 관측을 유지한 별도 로컬 실행이다. 실제 CCTV 추론·물리 단말 ACK·현장 대피 성능 검증을 뜻하지 않는다.

### 점진적 확산 부하 검증

`python -m tools.room_load --origin http://127.0.0.1:8047 --rooms 5 --signs 2 --minutes 30 --server-pid <PID> --progressive-fire`로 각 방에서 위치 지정 화재를 120초간 유지한 뒤 해제한다. 화면과 같은 위치 입력 검증을 거치며, 각 방의 확산 필드 수신·안내 버전 변경과 응답 크기도 보고한다. AI 설정이 없을 때의 AI 요청 실패는 화재·경로 API 실패와 구분한다. 이 검사는 실제 AI 실행이나 운영 서버 성능을 보증하지 않는다.

완료된 확산 실행도 `tools.verify_run`으로 검사할 수 있다. 확산 결정은 활성 위치 지정 화재가 있을 때만 허용하며, 원점은 최초 수락 이벤트와 일치해야 한다.

## 화재 위치로 쓸 수 없는 구역

`F2-ROOM-W`(2층 이름 없는 방), `F3-VOID-N`(3층 위쪽 X 표시 공간), `F3-CENTER`(3층 가운데 블록)은 위치 지정 시연 화재를 받지 않는다. 공개 층별안내도에 문이나 벽 틈이 없어(공간 기준 U04·U05) 지점도 차단 대상도 없고, 불을 내도 경로가 바뀌지 않기 때문이다. 기준은 "구역에 지점이 없고 `blocked_node_ids`·`blocked_edge_ids`가 모두 비어 있음"이며 서버(`check_event`)와 화면(`fireSelectable`)이 같은 기준을 쓴다. 화면은 이유를 「시연 시작」 옆에 안내하고, 서버는 `INVALID_EVENT_COMBINATION`으로 거부한다. 위치 없는 일반 경보는 그대로 받는다. 이 구역들을 지원하려면 공간 자료에 실제 연결(문·통로)을 근거와 함께 보완해야 한다. `F2-VOID`는 차단 통로 4개가 있어 선택할 수 있고, 확산이 지점에 닿지 못하므로 구역 차단으로 대체한다.
