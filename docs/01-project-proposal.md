## 1 프로젝트 목표

건물에서 화재 또는 연기 관련 신호가 발생하면 관측된 위험 구역을 경로에서 제외하고, 각 지점의 유도등이 안내하는 방향을 갱신하는 제어 시스템을 개발한다. 대피자는 갈림길마다 표시되는 방향을 따라 이동할 수 있어야 한다.

평상시에는 설정된 기본 안내를 표시한다. 화재 상황에서는 관측된 위험과 통로 상태에 따라 안내 방향을 변경한다. 인접한 유도등은 하나의 안내 결과를 공유하며, 서로를 반복해서 가리키거나 차단 구간으로 안내해서는 안 된다.

이번 개발의 핵심 연결은 다음과 같다.

```text
녹화 영상 → 오픈소스 불꽃·연기 AI ─┐
연기감지기·스프링클러 모의 신호 ┴→ 제어 백엔드
                                  구역 상태 통합 → 경로 계산 → 유도등별 명령
                                                                │
                                            ┌───────────────────┤
                                            ↓                   ↓
                                  별도 유도등 단말         관제·3D 화면
                                  수신·표시·적용 응답      관측 상태·경로 표시
```

제어 백엔드와 유도등 단말은 실제 프로그램으로 실행한다. 3D 화면을 닫아도 감지 입력, 경로 계산, 단말 안내와 기록은 계속 동작해야 한다. 화면에서 경로를 임의로 그리거나 유도등 방향을 별도로 결정하지 않는다.

별도 Bedrock 작업자는 확정된 상태·차단·경로를 읽어 관제에 현재 상황과 경로 선택 이유를 설명한다. 이 설명은 관측·경보 해제·유도등 제어 입력으로 되돌리지 않는다. 설명 호출을 기다리느라 경로와 단말 갱신을 늦추지 않으며 실패·지연·오래된 버전은 화면에서 구분한다.

이번 결과물은 가상 설비 환경에서 실제 영상 분석·경로 계산·명령 전달을 검증하는 제어 프로토타입이다. 실제 설비로 확장할 때는 입력·출력 연결 모듈을 추가하고 장비별 통신·전원·고장 대응을 별도로 검증한다. 연결 모듈 교체만으로 현장 적용이 완료된다고 가정하지 않는다.

## 2 해결할 문제와 검증 범위

고정 방향 안내는 화재로 특정 복도·계단·출구가 이용 불가능해진 상황을 반영하지 못한다. 건물 전체 상황을 알기 어려운 대피자에게 각 위치에서 다음 이동 방향을 제공하는 것이 이 프로젝트가 해결할 문제다.

이번 개발에서는 다음을 검증한다.

- 감지 결과가 올바른 건물 구역과 연결되는가.
- 위험 상태 변화가 경로와 유도등 안내에 실제로 반영되는가.
- 연기 영역이 시간에 따라 달라지고 새 감지 이벤트가 전달될 때 안내를 갱신하는가.
- 전체 유도등의 안내를 따라가면 조건을 충족한 목적지에 도달하는가.
- 제어 명령이 별도 유도등 단말에 전달되어 올바른 방향으로 표시되는가.
- 경로를 제공할 수 없거나 정보가 부족할 때 그 이유를 구분하는가.
- 영상 또는 통신 장애 이후 오래된 정보를 현재 안내로 사용하지 않는가.

관측하지 못한 위험, 실제 연기 확산, 군중 행동을 포함한 건물의 피난 안전성은 이번 소프트웨어 시험만으로 입증하지 않는다. 정확도와 반응 시간은 구현 후 측정하며, 측정 전 수치를 성능으로 기재하지 않는다.

## 3 건물 데이터와 시뮬레이션 가정

### 3.1 확보된 건물 정보

공식 시설 안내에는 지하 1층, 지상 1~3층, 4층 옥상이 기재되어 있으며, 공개된 층별안내도는 1~3층이다. 이번 건물 모델은 공개 안내도의 방·복도·계단 배치를 참고한다. [공식 시설 안내](https://wfi.or.kr/communication/?b=B_1_4)

기존 PDF의 5층 그림은 생성된 콘셉트 이미지이므로 건물 모델의 원본으로 사용하지 않는다.

### 3.2 시연을 위해 설정할 정보

실제 설비 자료는 확보되지 않았다. 다음 정보는 팀이 시연용으로 설정하고, 실제 설치 정보와 구분해 관리한다.

| 데이터 | 처리 원칙 |
| --- | --- |
| CCTV 위치와 관측 영역 | 가상 카메라와 관측 구역을 배치하고 영상 입력과 연결 |
| 연기감지기 위치 | 가상 감지기 ID와 담당 구역 지정 |
| 스프링클러 신호 범위 | 개별 발화 좌표가 아닌 가상 담당 구역으로 지정 |
| 유도등 위치와 표시면 방향 | 갈림길·계단·출입구의 가상 설치 지점과 보는 방향 지정 |
| 출구와 통행 가능 조건 | 안내도에서 확인한 구조에 시연용 통행 조건을 부여하고 가정임을 표시 |
| 거리와 층 높이 | 실측값이 없으면 모델용 값임을 명시. 실제 이동 시간 산정 근거로 사용하지 않음 |

초기 개발 범위는 공개 안내도가 있는 지상 1~3층이다. 지하층과 옥상은 연결 구조·목적지 조건이 확인되지 않아 기본 경로에 포함하지 않는다. 대체 대피공간 안내는 핵심 기능 완료 후 별도로 검토한다.

우회 시연을 위해 안내도에 없는 통로나 계단을 추가하지 않는다. 연결 구조가 불명확한 구간은 확인 항목으로 남기고, 선택한 모델링 가정은 건물 데이터와 시나리오에 기록한다.

### 3.3 입력과 출력의 구현 방식

| 구분 | 이번 구현 |
| --- | --- |
| CCTV 입력 | 녹화 영상에 실제 불꽃·연기 AI 추론 수행. 영상과 건물 구역은 수동 매핑 |
| 설비 입력 | 시험 도구에서 연기감지기·스프링클러 이벤트를 발생시켜 제어 백엔드에 전달 |
| 판단과 경로 | 제어 백엔드가 수신한 관측 이벤트와 건물 설정으로 실제 계산 |
| 유도등 출력 | 유도등 ID별 명령을 별도 브라우저 단말에 전송하고 적용 결과 확인 |
| 연기 변화 | 시간에 따른 구역별 연기 상태를 시나리오로 생성하고 3D에 시각화 |
| 장애 상황 | 관측 지연·누락, 영상 끊김, 단말 단절·오래된 명령 등을 시험 입력으로 재현 |

AI 추론 이벤트와 수동 시험 이벤트는 화면과 로그에서 구분한다. 모의 감지 결과를 실제 AI 추론 결과로 표시하지 않는다. 녹화 영상 분석은 실제 건물 CCTV와 연동한 것으로 소개하지 않는다.

### 3.4 연기 변화와 관측 정보의 분리

연기는 발화 구역에서 올라와 공간에 차오르고, 시나리오에서 지정한 인접 구역으로 영역이 확대되는 모습을 표현한다. 구역별 연기 상태와 표현 강도는 시험을 위한 값이며 실제 농도·독성 또는 물리적 확산 예측값으로 사용하지 않는다. 고급 연기 효과보다 구역 변화와 경로 갱신의 연결을 우선한다.

시험 환경이 알고 있는 연기 상태와 제어 백엔드가 관측한 위험 상태를 분리한다.

```text
연기 변화 시나리오 ─→ 시험용 연기 상태 ─→ 3D 연기 표현·시험 정답
                              │
                              └─→ 가상 감지기 관측 생성
                                  지연·누락·고장 조건 적용
                                           ↓
                                      제어 백엔드
                                           ↓
                                  경로·유도등 명령 갱신
```

제어 백엔드는 시험 정답을 직접 읽지 않고, 전달받은 감지 이벤트만 사용한다. 관제 화면에서도 시험용 연기 표현과 제어기가 관측한 위험 표시를 구분한다. 연기 애니메이션의 재생 시점에 맞춰 경로나 화살표를 미리 변경하지 않는다.

녹화 영상의 실제 감지를 시나리오 시작 조건으로 사용할 수 있다. 이후 설정에 따라 확대되는 연기와 가상 감지 신호는 모의 입력으로 기록하며, AI가 연기 확산을 예측하거나 추가 구역을 실제 관측한 것으로 표시하지 않는다. 시나리오 시간과 입력 발생 순서를 기록해 반복 시험할 수 있게 한다.

## 4 구현 우선순위

### 4.1 필수 기능

아래 기능은 화요일 핵심 기능 완료 범위다. 완료 여부는 화면의 존재가 아닌 연결 동작과 시험 결과로 판단한다.

| ID | 기능 | 완료 기준 |
| --- | --- | --- |
| F01 | 불꽃·연기 영상 분석 | 실제 추론 결과에 관측원, 영상 시각, 감지 종류, 신뢰도와 연결 구역을 제공 |
| F02 | 설비 신호 시뮬레이션 | 연기감지기·스프링클러 신호가 각각 독립적으로 구역 상태와 경로에 반영 |
| F03 | 위험 상태 통합 | 원인별 경보 유지·확인 해제·관측 불가 처리. 다른 관측원의 미검출로 경보를 삭제하지 않음 |
| F04 | 경로 계산 | 관측된 위험 구간을 제외하고 설정된 출구까지 계산. 도달 불가이면 이유와 함께 안내 불가 반환 |
| F05 | 가변 유도등 안내 | 지점·표시면에 맞는 방향을 출력하고 전체 안내의 순환·방향 모순 검사 |
| F06 | 기본 건물·관제 화면 | 지상층 건물 모델에 시험용 연기와 관측 위험을 구분해 표시. 계산 경로·유도등은 동일 안내 버전으로 표시 |
| F07 | 반복 실행과 기록 | 시나리오 초기화·재실행이 가능하고 입력·상태·안내 변경 원인과 시각을 기록 |
| F08 | 기본 장애 처리 | 영상 입력·화면·단말의 단절, 지연·역순 명령을 시험하고 오래된 안내의 적용 방지 |
| F09 | 연기 변화 시연 | 구역별 연기 변화가 가상 감지 이벤트를 거쳐 경로와 유도등 방향 변경으로 연결 |
| F10 | 별도 유도등 단말 | ID별 명령 수신·표시·적용 응답 확인. 3D 화면 종료 후에도 제어와 단말 안내 유지 |
| F11 | Bedrock 상황 설명 | 현재 실행·안내 버전에 맞는 관측 근거와 경로 선택 이유를 설명. 설명 실패 중에도 제어 유지 |

## 5 핵심 동작 원칙

### 5.1 감지와 상태 통합

불꽃·연기 AI와 설비 신호는 각각 위험 근거가 될 수 있다. 모든 입력이 동시에 경보를 내야만 작동하는 방식으로 만들지 않는다. 영상 감지는 지속 조건을 적용하고, 해당 조건과 임계값은 설정으로 관리한다.

경보 상태와 관측 유효성은 분리한다. 정상 분석 후 미검출된 상태, 가림으로 판단하기 어려운 상태, 새 관측을 받지 못한 상태를 구분한다. 설비는 경보 이벤트의 부재와 장치 상태 확인 실패를 구분한다.

활성화된 화재·연기·스프링클러 경보는 해당 원인의 확인 해제 입력이 있을 때 해제한다. 영상 종료, 재접속 또는 다른 센서의 정상 결과만으로 해제하지 않는다. 확인 해제는 이번에는 시뮬레이터 조작으로 구현한다.

### 5.2 경로와 목적지

건물은 교차점·계단·출입구를 나타내는 지점과 이동 가능한 통로의 연결 구조로 표현한다. 제어기가 위험으로 판정한 구간을 먼저 제외한 뒤 사용 가능한 연결에서 경로를 계산한다. 위험 구간에 큰 비용만 부여하여 대안이 없을 때 통과시키는 방식은 사용하지 않는다.

경로 계산의 초기 구현안은 여러 출구에서 역방향으로 탐색해 각 지점의 다음 이동 지점을 구하는 방식이다. 통로 비용은 양수로 두고, 동일 상태에서는 같은 결과를 반환하도록 동률 처리 규칙을 정의한다. 세부 알고리즘과 데이터 형식은 상세설계서에서 확정한다.

관측이 필수인 구간의 정보가 유효하지 않으면 화재 상황의 경로 후보에서 제외한다. 안내 불가의 원인은 통로 차단, 정보 부족, 목적지 조건 미충족, 시스템 장애로 구분한다. 안내 불가를 해당 위치의 안전 또는 대기 지시로 해석하지 않는다.

닫힌 문과 통과 불가능한 문은 구분한다. 시연 모델에서 문 개폐 상태와 통행 가능 여부를 별도로 설정한다.

### 5.3 유도등과 화면

유도등은 개인의 위치가 아닌 설치 지점을 기준으로 안내한다. 실제 사람 추적은 필요하지 않으며, 이동하는 표시점은 안내를 따라가는 시연용으로만 사용한다.

각 유도등은 다음 이동 지점과 표시면 방향을 이용해 화살표를 표시한다. 경로·유도등·위험 표시는 같은 안내 버전을 사용한다. 화면에서 독립적으로 방향이나 경로를 계산하지 않는다.

정상 관측 상태의 기본 표시와 화재·관측 장애 시의 동적 안내를 구분한다. 운전 중 필수 관측이 끊기면 장애 상태를 유지하면서 해당 구역을 제외해 경로를 다시 계산하고, 출구에 도달할 수 있는 지점은 계속 안내한다. 기본 방향이나 이전 방향을 안전한 대피 경로로 자동 유지하지 않으며, 초기화·명령 만료 시에는 방향을 제거한다. 실제 설비의 고장 시 표시 정책은 별도 현장 설계 대상으로 남긴다.

### 5.4 소프트웨어 구성과 저장 책임

| 구성 | 책임 | 이번 구현 범위 |
| --- | --- | --- |
| AI 모듈 | 녹화 영상 분석과 감지 이벤트 생성 | 불꽃·연기 추론, 영상·관측원 정보 제공 |
| 제어 백엔드 | 관측 상태 통합, 경로 계산, 명령 생성·전송 | 시험 도구나 3D 화면의 경로 결정에 의존하지 않는 핵심 프로그램 |
| 관제 프론트엔드 | 영상 근거, 관측 상태, 경로·3D 표시 | 서버 결과 표시와 시험 조작. 경로 계산은 백엔드에 요청 |
| 유도등 단말 | 자기 ID의 명령 수신과 표시 | 별도 브라우저 창 또는 보유 기기의 화면에서 실행 |
| 시험 도구 | 연기 시나리오와 설비·장애 입력 생성 | 정답 상태, 관측 이벤트, 기대 결과 관리 |
| 데이터 저장 | 건물·설비 설정과 실행 증거 보존 | 설정 파일과 로그부터 시작. 조회 필요에 따라 작은 로컬 DB 사용 |

현재 위험 상태와 경로 계산은 메모리에서 처리하고, 입력·판단·명령·적용 결과를 실행 단위로 저장한다. 별도의 DB 전담자는 두지 않으며 저장 책임은 백엔드 담당이 맡는다. Python 3.12·FastAPI와 React·TypeScript·Three.js를 사용하며 JSON 설정·JSONL 로그로 시작한다. 초기 연결은 HTTP 이벤트 전송과 단말의 주기 조회를 기준으로 한다. 실행 절차와 세부 계약은 개발계획서·데이터 명세서에 정의한다.

### 5.5 단말 적용 확인

명령 생성, 전송, 단말 수신, 표시 적용은 구분해 기록한다. 단말은 유도등 ID와 안내 버전 등 유효성을 확인하고 적용 결과를 반환한다. 적용 응답과 화면 확인을 함께 사용해 전송 성공만으로 표시 성공을 판정하지 않는다.

일부 단말이 새 명령을 받지 못한 상태와 모든 단말에 같은 안내가 적용된 상태를 구분한다. 단말 단절·재접속·오래된 명령의 처리 규칙은 인터페이스 명세서에서 정의하고, 정상 흐름과 함께 시험한다. 명령 수신·적용 지연은 3D 화면 반영 지연과 별도로 측정한다.

### 5.6 지원 서버 활용과 배포

사용자가 제공한 `4조_서버안내.html`에는 Ubuntu 24.04·4코어·16GB·30GB 서버, SSH 키 접속, 서버 권한을 통한 AWS 사용과 S3 버킷이 안내되어 있다. 실제 접속 가능 여부·자원·권한은 착수 단계에서 확인한다. GPU는 확인되지 않았다.

서버에서 제어기·AI·시나리오를 실행하고, S3는 확보 자료와 실행 증거 보관에 사용한다. 화요일 핵심 완료에 서버 통합 배포를 포함하고 수요일에 접속·재시작·복구를 검수한다. 공개 주소와 도메인은 미정이므로 기본은 팀 전용 SSH 터널 접속이다. 공개 제출이 필요해지면 읽기 전용 관람과 인증된 조작을 구분한다.

제공되는 Bedrock은 F11 상황 설명에 사용한다. 화재 감지는 공개 불꽃·연기 모델, 대피 경로·유도등 결정은 제어기가 담당한다. Bedrock이 새로운 위험·통로·이동 지시를 생성하거나 경보를 해제하지 않는다. SSH 개인키·AWS 자격증명은 저장소·웹·로그에 포함하지 않는다. 행사 종료 후 서버·저장소 삭제가 예정되어 있어 GitHub와 PC에 제출본·증거를 보관한다.

## 7 역할 분담안

아래는 산출물과 검수 책임에 따른 분담안이다. 5명 모두 코딩을 맡을 필요는 없다. AI를 활용하더라도 각 담당은 자기 결과물의 정확성과 연결 상태를 확인한다. 팀원 이름과 사용 가능한 개발 환경은 개발계획서에서 연결한다.

| 담당 | 주 책임 | 다른 담당에게 제공할 결과 |
| --- | --- | --- |
| 1 | 오픈소스 불꽃·연기 AI, Bedrock 상황 설명 | 감지 이벤트·설명 결과를 별도로 인계, 모델·설정·평가 근거 |
| 2 | 백엔드·경로·데이터 저장·서버 배포 | 상태 통합, 경로·명령, 전송·기록, 공통 실행·서비스 |
| 3 | 프론트엔드·유도등 단말 | 모델 로딩, 연기 표현, 관제 화면, 별도 단말의 명령 적용 |
| 4 | 건물 3D 모델링·공간 데이터 | 층·벽·복도·계단 모델, 구역 ID와 좌표, 가상 설비 배치 자료 |
| 5 | 데이터·시험·통합 관리 | 평가 영상과 기대 결과, 연기·장애 시나리오, 오류 재현, 실행·제출 점검 |

4번은 건물 형태와 공간 배치를 맡고, 3번은 이를 화면에 불러와 연기·경로·유도등 상태를 표시한다. 2번은 4번과 확인한 공간 연결을 경로 계산용 그래프로 구성한다. 모델 제작과 프론트엔드 동작 구현을 하나의 작업으로 묶지 않는다.

3D 제작은 안내도를 검토해 정한 공간 데이터를 바탕으로 AI의 도움을 받아 벽·바닥·계단을 코드로 생성하는 방식부터 시작한다. 특정 3D 편집 도구를 필수로 두지 않는다. 생성 결과는 통로 연결과 층별 정합성을 검수하고, 모델이 완성되기 전에도 단순한 형태로 제어 기능을 연결한다.

2·3·4번은 건물·구역·통로·유도등 식별자와 좌표 기준을 먼저 맞춘다. 1·2·5번은 감지 이벤트 형식을, 2·3·5번은 유도등 명령과 적용 응답 형식을 맞춘다. 5번은 코딩 비중이 낮아도 초기부터 시험 입력과 독립적인 기대 결과를 준비한다. 백엔드에 작업이 집중되므로 공통 샘플로 먼저 연결하고 기능 추가보다 통합을 우선한다.

### 8.1 필수 검증 사례

- 불꽃과 연기 입력이 각각 구역 상태와 경로 변경으로 연결된다.
- 연기감지기와 스프링클러 모의 입력이 각각 독립적으로 반영된다.
- 연기 시나리오의 새 관측 이벤트가 경로와 별도 단말 방향 변경으로 연결된다.
- 제어기가 위험으로 판정한 구간을 포함하는 안내 경로가 생성되지 않는다.
- 도달 가능한 각 지점에서 유도등 안내를 따라가면 목적지에 도달하며 순환하지 않는다.
- 모든 대안을 잃은 지점은 안내 불가로 표시된다. 다른 지점의 유효한 안내는 유지한다.
- 미검출·단절·재접속만으로 기존 경보가 해제되지 않는다.
- 낮은 버전의 결과가 최신 경로·유도등 표시를 덮어쓰지 않는다.
- 일부 단말의 단절·적용 실패를 전체 적용 성공으로 기록하지 않는다.
- 3D 화면을 종료해도 영상 분석·제어·별도 단말 안내와 기록이 계속 동작한다.
- 제어 백엔드가 시험 정답을 직접 사용하지 않으며, 관측 지연·누락이 시험 결과에 드러난다.
- 같은 시나리오를 초기화하여 반복 실행할 수 있다.

### 8.2 기술 검증 방법과 증거

| 검증 대상 | 방법 | 남길 증거 |
| --- | --- | --- |
| 실제 AI 감지 | 원본 영상·장소 단위로 학습·조정용과 평가용 영상을 분리. 정상·혼동 장면과 불꽃·연기 장면 평가 | 클래스별 정밀도·재현율, 오탐·미탐 사례, 감지 지연, 모델·설정·장비·평가 데이터 목록 |
| 경로 계산 | 작은 연결 구조에서 사람이 별도로 확인한 기대 결과와 비교. 도달 가능한 모든 지점의 안내 추적 | 위험 구간 포함·순환·잘못된 목적지 사례, 제공해야 할 경로의 제공 여부 |
| 명령 전달과 표시 | 별도 브라우저 단말에 실제 명령 전송. 적용 응답과 화면 확인, 단절·지연·역순 명령 시험 | 입력부터 계산·전송·적용까지 연결되는 기록, 단말별 버전·적용 상태와 지연 |
| 연기 변화 대응 | 시험 정답과 관측 이벤트를 분리하고 지연·누락·고장 조건을 주입 | 정답 위험 상태와 제어기 관측의 차이, 경로 변경 시각, 잔여 위험·안내 불가 사례 |
| 독립 실행과 재현성 | 3D 화면 종료 상태에서 제어 실행. 동일 설정·입력 순서로 초기화 후 재시험 | 실행 절차, 설정·시나리오 버전, 반복 실행 결과 |

경로 정확성은 제어기가 가진 유효한 관측을 기준으로 검사한다. 별도로 시험 정답과 비교해 감지 지연·미탐 때문에 아직 알려지지 않은 위험 구간을 안내했는지도 기록한다. 전자는 판단 로직의 정확성, 후자는 감지부터 안내까지 연결한 결과의 한계를 보여준다.

항상 안내 불가를 반환하는 구현을 성공으로 평가하지 않는다. 기대 경로가 있는 지점에서의 경로 제공 여부와 불필요한 안내 불가를 함께 측정한다. 감지 지연, 상태 판단·경로 계산, 명령 전송·단말 적용, 관제 화면 반영 시간을 구분하고 시험 조건과 함께 보고한다.

이 시험으로 입증할 범위는 평가 영상에서의 감지 성능, 지정 시나리오에서의 경로 계산, 소프트웨어 명령 전달과 표시, 장애 대응이다. 실제 연기 확산의 정확성, 소방용 유도등의 전기·비상전원 성능, 실제 피난시간 단축이나 인명 피해 감소는 입증 범위에 포함하지 않는다. 목표치와 통과 기준은 평가 전에 정하고, 측정 결과를 보고 기준을 낮추지 않는다.
