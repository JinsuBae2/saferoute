# WFI 창업지원허브 공간 기준 (M01·M02)

원주미래산업진흥원 창업지원허브의 공개 층별안내도를 바탕으로 공간 ID·좌표·가정을 정리한 문서다. 2번(그래프)과 3번(3D 표시)이 같은 ID와 좌표 규칙을 쓰도록 하는 기준이며, 실제 공간 JSON은 M02에서 이 규칙대로 만들었다(10절). 필드 정의는 [데이터·인터페이스 명세서 2절](../../docs/05-data-interface-spec.md#2-공간-자료)을 따른다.

이 문서는 공개 안내도를 사람이 판독한 결과다. 실측 도면이 아니며, 설비 배치·치수·통행 조건은 시연 가정이다. 기존 기획 PDF의 생성된 5층 이미지는 도면으로 쓰지 않는다.

## 1. 출처

| 항목 | 내용 |
| --- | --- |
| 건물 | 원주미래산업진흥원 창업지원허브, 강원특별자치도 원주시 마재2로 10 |
| 안내 페이지 | [시설 및 입주 안내](https://wfi.or.kr/communication/?b=B_1_4) |
| 안내도 이미지 | `img-facility-1F.png`, `img-facility-2F.png`, `img-facility-3F.png` (페이지 기준 `../../assets/images/content/`) |
| 원본 크기 | 1F 5461×3859 px, 2F·3F 5456×3855 px |
| 확인일 | 2026-11-08 |
| 범위 | 공개 안내도가 있는 지상 1~3층. 공식 안내의 지하 1층·4층 옥상은 안내도가 없어 제외 |

안내도 이미지는 진흥원 자료이므로 저장소에 넣지 않는다. 필요한 사람은 위 페이지에서 직접 받는다.

공간 JSON의 `provenance`([명세 10.3절](../../docs/05-data-interface-spec.md#103-공간의-세부-객체))에는 `source_url`에 위 안내 페이지, `checked_on`에 `2026-11-08`, `description`에 공개 안내도 판독·실측 아님을 적는다.

## 2. 좌표계

| 항목 | 기준 |
| --- | --- |
| 단위 | m. 실측이 아니므로 공간 JSON의 `coordinate_system`에 `measured: false`를 둔다 |
| 축 | 명세 2.1절과 같이 y가 높이, 안내도 오른쪽이 +x, 안내도 위쪽이 -z |
| 방위 | 안내도 위쪽이 실제 북쪽인지는 확인하지 못했다. 이 문서의 N·S·W·E는 **안내도 위·아래·왼·오른쪽**을 뜻한다 |
| 원점 | 2층 외곽 벽의 안내도 왼쪽 위 모서리를 (x=0, z=0)으로 한다. 2층과 3층은 외곽이 거의 같고 가장 넓다 |
| 축척 | 원본 이미지 1 px ≈ **0.0125 m** (아래 추정 근거) |
| 층 높이 | 층마다 **4.0 m**로 가정한다. F1 y=0, F2 y=4.0, F3 y=8.0 |

M02에서는 노드·구역·벽 좌표를 **이미 건물 좌표(m)로 바꾼 값**으로 저장한다. 노드의 y에는 층 높이가 들어 있으므로 `floor_transforms`는 모든 층에서 항등 변환(scale 1, translation 0)이다. 소비하는 쪽이 변환을 한 번 더 적용해도 결과가 바뀌지 않게 하려는 선택이다. 안내도 px를 m로 바꾼 값은 2.2절 표에 남긴다. M01 초안의 "scale 0.0125, translation y 4·8" 안은 쓰지 않는다.

```json
{
  "unit": "m",
  "measured": false,
  "up_axis": "+y",
  "plan_right_axis": "+x",
  "plan_up_axis": "-z",
  "origin": {"x": 0.0, "y": 0.0, "z": 0.0},
  "floor_transforms": [
    {"floor_id": "F1", "scale": 1.0, "translation": {"x": 0.0, "y": 0.0, "z": 0.0}},
    {"floor_id": "F2", "scale": 1.0, "translation": {"x": 0.0, "y": 0.0, "z": 0.0}},
    {"floor_id": "F3", "scale": 1.0, "translation": {"x": 0.0, "y": 0.0, "z": 0.0}}
  ]
}
```

### 2.1 축척 추정 근거

공개 페이지의 호실 면적과 안내도에서 읽은 방 크기를 비교했다. 방 경계는 판독한 근사값이다.

| 기준 방 | 공개 면적 | 원본 px당 길이 |
| --- | --- | --- |
| 1F 컨퍼런스룸 | 180 m² | 0.0124 m |
| 2F 201호 | 90 m² | 0.0126 m |
| 3F 305호 | 90 m² | 0.0121 m |
| 3F 302호 | 47 m² | 0.0131 m |
| 3F 301호 회의실 | 47 m² | 0.0125 m |

다섯 값의 평균이 약 0.0125 m이고 편차는 약 ±5%다. 이 축척으로 2·3층 외곽은 약 44 m × 28 m, 1층은 약 44 m × 22 m다.

### 2.2 층 정렬

세 안내도는 같은 위치·크기로 그려지지 않았다. M02에서 층마다 원본 px를 건물 좌표로 옮긴 값은 다음과 같다. `x = (px_x - 원점 px_x) × 축척`, `z = (px_y - 원점 px_y) × 축척`.

| 층 | 원점 px (x, y) | 축척 (m/px) | 맞춘 기준 |
| --- | --- | --- | --- |
| F1 | (1760, 717) | 0.0125 | x는 외곽 왼쪽 벽, z는 계단 A·B 중심 높이를 2F에 맞춤 |
| F2 | (1777, 959) | 0.0125 | 외곽 왼쪽 위 모서리 (원점) |
| F3 | (1808, 922) | 0.01261 | 외곽 네 변을 2F 외곽 크기에 맞춤 |

- 2F·3F는 외곽 벽의 오른쪽 끝과 위·아래 벽을 기준으로 맞췄다. 3F 안내도가 약 1% 작게 그려져 축척을 따로 둔다.
- 1F는 외곽이 2·3F보다 짧아(z 약 5.7~27.4 m) 계단 A·B 위치로 맞췄다. 계단 A는 층마다 1 m 안쪽으로 맞지만, 계단 B는 1F에서 약 3 m 오른쪽에 그려져 있다(U03).

## 3. ID 규칙

모든 ID는 영어 대문자·숫자·하이픈을 쓴다. 화면 라벨(한글 호실명)은 `label`에 두고 ID와 섞지 않는다.

| 대상 | 형식 | 예 |
| --- | --- | --- |
| 건물 | `WFI` | `WFI` |
| 층 | `F<층>` | `F1`, `F2`, `F3` |
| 구역 | `<층>-<이름>` | `F2-R201`, `F1-LOBBY`, `F2-CORR-N` |
| 노드 | `<층>-<종류>-<이름>` | `F2-J-N1`, `F2-D-R201`, `F2-S-A`, `F1-X-N` |
| 통로 | `E-<출발 노드>-<도착 노드>` | `E-F2-J-N1-F2-S-A` |
| 출구 | `EXIT-<이름>` | `EXIT-N` |
| 유도등 | `SIGN-<노드>` | `SIGN-F2-J-N1` |
| 관측원 | `<CAM\|SMK\|SPK>-<구역>` | `CAM-F2-CORR-N`, `SPK-F3-R305` |

- 노드 종류 문자는 명세의 node.kind와 1:1로 대응한다: `J` JUNCTION, `D` DOOR, `S` STAIR, `X` EXIT.
- 통로는 방향이 있으므로 양방향 이동은 `E-A-B`와 `E-B-A`를 모두 등록한다.
- 계단 노드의 이름은 층과 상관없이 같은 계단 문자를 쓴다. 예: 계단 A는 `F1-S-A`, `F2-S-A`, `F3-S-A`.
- 구역 이름: 호실 `R<번호>`, 복도 `CORR-<방향>`, 계단실 `STAIR-<문자>`, 그 외는 아래 표의 이름을 쓴다. 같은 방향 복도가 둘이면 바깥쪽에 숫자를 붙인다(`CORR-E2`).

## 5. 가상 설비 배치 가정

실제 건물의 카메라·감지기·스프링클러·유도등 위치는 공개 자료로 확인할 수 없다. 아래 배치는 시연을 위한 **가상 설비**이며, 화면과 데이터에서 실제 설비처럼 표시하지 않는다. 정확한 좌표는 M02에서 구역·노드 위치에 맞춰 정한다.

### 5.1 관측원

| 유형 | 명세 source_type | allowed_hazard_types | 배치 기준 | 초기 목록 |
| --- | --- | --- | --- | --- |
| 영상 AI 카메라 | `VIDEO_AI` | `FIRE`, `SMOKE` | 영상 하나를 구역 하나에 연결한다(명세 2.2절). 계단 A·B 쪽 우회가 보이도록 2·3F 왼쪽·오른쪽 복도에 둔다 | `CAM-F2-CORR-W`, `CAM-F2-CORR-E`, `CAM-F3-CORR-W`, `CAM-F3-CORR-E` |
| 연기감지기 | `SIM_SMOKE_DETECTOR` | `SMOKE` | 복도·로비·뚫린 공간 구역마다 1개, 구역 가운데 천장 | `SMK-F1-LOBBY`, `SMK-F1-PASSAGE`, `SMK-F2-VOID`, `SMK-F2-CORR-N`, `SMK-F2-CORR-W`, `SMK-F2-CORR-E`, `SMK-F3-CORR-N`, `SMK-F3-CORR-W`, `SMK-F3-CORR-E` |
| 스프링클러 | `SIM_SPRINKLER` | `SPRINKLER` | 헤드·배관이 아닌 **구역 단위 신호**로 모델링한다. 복도·로비 구역마다 1개 | 연기감지기와 같은 구역에 `SPK-` 접두어로 둔다 |

- 카메라 수는 1번이 준비하는 영상 수에 맞춘다. 영상이 부족하면 위 순서대로 줄이고, 빠진 구역은 연기감지기·스프링클러 신호로 시연한다.
- 호실 안쪽에는 관측원을 두지 않는다. 대피 판단은 복도·계단·로비의 통행 가능 여부로 한다.
- `required`와 `freshness_ms` 값은 2번이 상태 관리 규칙에 맞춰 정한다.

### 5.2 유도등

| 위치 | 기준 | 표시면 |
| --- | --- | --- |
| 복도 갈림길 | 두 방향 이상으로 갈 수 있는 `J` 노드마다 1개 | 복도 방향에 따라 `FRONT`·`REAR` 두 면 |
| 계단 입구 | 각 층 계단 A·B 노드(`F2-S-A` 등) | 2·3F에서 계단으로 내려가는 방향은 `STAIRS_DOWN` |
| 출구 | 활성 출구 노드 `F1-X-N`, `F1-X-S` 자체 | 자기 노드 → `EXIT`, `default_next_node_id`도 자기 노드 |

- 표시값은 명세 2.2절의 `LEFT`·`RIGHT`·`FORWARD`·`BACK`·`STAIRS_UP`·`STAIRS_DOWN`·`EXIT`만 쓴다.
- 명세 2.2절에 따라 `EXIT` 표시는 활성 출구 노드에 있는 유도등에서만 쓴다. 출구 앞 갈림길 유도등은 출구 노드 방향을 `LEFT`·`FORWARD` 등으로 표시한다. 자기 자신으로 향하는 통로는 만들지 않는다.
- 표시면 방향(`view_direction`)과 다음 지점별 표시는 M02에서 노드 위치가 정해진 뒤 정하고, M03에서 3번과 사람 시점으로 대조한다.

## 7. 읽는 법 예시

아래는 ID와 좌표를 해석하는 예시다. 경로 계산 결과나 정답이 아니며, 실제 노드 이름과 연결은 M02 자료에서 정해진다.

**ID 해석**

| ID | 뜻 |
| --- | --- |
| `F2-R201` | 2층 201호 구역 |
| `F2-CORR-N` | 2층 위쪽 복도 구역 |
| `F2-D-R201` | 2층 201호 문 노드 |
| `F2-S-B` | 2층의 계단 B 노드. `F1-S-B`, `F3-S-B`와 STAIR 통로로 이어진다 |
| `E-F2-S-B-F1-S-B` | 2층 계단 B에서 1층 계단 B로 내려가는 방향의 통로 |
| `SIGN-F2-S-B` | 2층 계단 B 입구 앞 유도등 |

**좌표 해석**

원본 안내도에서 2층 외곽 왼쪽 위 모서리로부터 오른쪽 800 px, 아래쪽 400 px 떨어진 점은 다음과 같다.

```json
{"x": 10.0, "y": 4.0, "z": 5.0}
```

x = 800 × 0.0125 = 10.0 m, 높이는 2층이므로 y = 4.0 m, 안내도 아래쪽은 +z이므로 z = 400 × 0.0125 = 5.0 m다.

**ID로 적은 이동 예시**

2층 201호에서 계단 B로 내려가 1층 위쪽 출구로 나가는 이동은 다음처럼 적는다.

```text
F2-D-R201 → F2-CORR-N 의 J 노드 → F2-S-B → F1-S-B → F1-PASSAGE 의 J 노드 → F1-X-N (EXIT-N)
```

## 10. M02 공간 자료

M01 규칙대로 만든 1~3층 자료다. 두 파일은 같은 좌표계(2절)를 쓴다.

| 파일 | 내용 | 쓰는 사람 |
| --- | --- | --- |
| `wfi-v1.json` | 명세 2절 Building 계약 그대로. 구역 42, 노드 79(갈림길 42, 문 23, 계단 10, 출구 4), 통로 176(복도 116, 문 48, 계단 12), 관측원 26, 유도등 37, 가정 9 | 2번 그래프·상태, 3번 노드·유도등 위치 |
| `wfi-geometry-v1.json` | 3D 표시용 바닥·벽·뚫린 공간·계단 형상. 계약에 형상 필드가 없어(추가 필드 금지) 따로 둔다 | 3번 3D 표시 |

### 10.1 3D 형상 파일

| 필드 | 뜻 |
| --- | --- |
| `floors[].slab` | 층 바닥 외곽 (x·z 점) |
| `floors[].slab_holes` | 바닥에 뚫린 곳. 2F `F2-VOID` |
| `floors[].walls` | 벽 직사각형 `[x0, z0, x1, z1]`. 바닥(층 elevation)부터 `wall_height` 3.0 m |
| `stairs[]` | 계단 A~D의 평면 범위와 잇는 층. C·D는 `OPEN` |

벽은 안내도의 진한 선(밝기 100 미만)을 0.1 m 칸으로 바꾼 뒤 직사각형으로 합친 것이다. 문 틈은 안내도의 벽 끊김 그대로 비어 있다. 열린 계단 C의 난간 선 일부도 낮은 벽처럼 남아 있으니 3D에서 필요하면 계단 범위 안의 벽을 숨긴다. GLB는 만들지 않았다. 3번이 이 파일로 상자 벽을 그리면 ID·좌표 대응이 그대로 유지된다.

### 10.2 그래프 만드는 규칙

- 방마다 문 노드(`D`) 하나를 두고 가장 가까운 복도 갈림길과 DOOR 통로로 잇는다. 방 안을 지나가는 통로는 만들지 않는다.
- 같은 층 통로 cost는 두 노드 사이 직선 거리(m, 소수 첫째 자리)다. 실제 피난 시간이 아니다.
- 계단 통로 cost는 한 층에 10이다. 열린 계단 C·D는 우회 가중치 30을 더해 40이다(A04, 2번과 확정 전 임시값).
- 구역은 자기 안의 노드와 그 노드에 닿는 통로를 모두 막는다. 2F `F2-VOID`는 노드가 없지만 C·D 계단 통로를, `F3-CORR-E`는 D 계단 통로를 추가로 막는다.
- 엘리베이터, 화장실, `F2-ROOM-W`(문 미확인, U05), `F3-CENTER`·`F3-VOID-N`(정체 미확인, U04)에는 노드를 두지 않는다.
- 계단 C는 1F 로비 사선 계단 위쪽 끝(`F1-S-C`)에서 2F 뚫린 공간 오른쪽(`F2-S-C`)으로 이어진다고 보았다(A08). 계단 D는 2F 아래쪽 끝(`F2-S-D`)에서 3F 위쪽 복도(`F3-S-D`)로 이어진다.

### 10.3 관측원·유도등

- 관측원은 5.1절 목록에 M02에서 나눈 `F2-CORR-E2`·`F3-CORR-E2`의 연기감지기·스프링클러를 더했다. `required`는 연기감지기만 true, `freshness_ms`는 3000이다(A09). 2번이 상태 규칙에 맞춰 바꾸면 이 값만 고친다.
- 유도등은 세 방향 이상으로 갈 수 있는 갈림길, 2·3F 계단 A·B 노드, 활성 출구 `F1-X-N`·`F1-X-S`에 둔다.
- 갈림길 유도등의 `FRONT` 면은 평상시 다음 지점 쪽을 바라보는 사람 기준이고 `REAR`는 반대 방향이다. 표시값은 바라보는 방향과 다음 지점 방향의 각도로 정했다(앞 `FORWARD`, 뒤 `BACK`, 좌우 `LEFT`·`RIGHT`, 다른 층 `STAIRS_DOWN`·`STAIRS_UP`).
- `default_next_node_id`는 경보가 없을 때 활성 출구까지 cost가 가장 작은 다음 지점이다. 그래서 평상시에는 모두 계단 A·B와 `EXIT-N`·`EXIT-S`로 향한다.
